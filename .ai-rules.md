# Reglas Maestras de Programación - Pool Control 1.0

Este documento es la autoridad máxima para el comportamiento del Asistente de IA. Debe ser consultado antes de cada modificación de código.

## 1. Gestión de Cambios
- **Aprobación Obligatoria**: Antes de escribir código, se debe presentar un plan detallado: [Archivo] -> [Funcionalidad a modificar].
- **No Refactorización Silenciosa**: No se deben simplificar o cambiar nombres de funciones existentes si no es parte del requerimiento.
- **Build Tracking**: Incrementar el número de `build` en `src/lib/version.ts` en cada respuesta que contenga cambios de código.

## 2. Seguridad Multi-Sucursal (Path Isolation)
- **Scoped Data**: Todas las rutas de Firestore deben seguir el patrón: `sucursales/{sucursalId}/[coleccion]`.
- **Validation**: Antes de cualquier escritura, verificar que `sucursalId` sea válido y esté presente en el contexto del hook `useSucursal`.

## 3. Interfaz de Usuario y Estilos
- **UI Freeze**: Prohibido modificar `globals.css`, configuraciones de Tailwind o clases CSS existentes a menos que el usuario lo pida específicamente.
- **Toasts**: Las notificaciones deben durar 5 segundos, mostrarse en la parte inferior en móviles y cerrarse automáticamente.

## 4. Lógica de Negocio e Inventario
- **Atomicidad**: Operaciones de Ventas, Stock y Correlativos deben usar `runTransaction`.
- **Clock Sync**: Usar `serverTimestamp()` para registros financieros. No confiar en `new Date()` del cliente para persistencia.
- **Form Cleanliness**: Ejecutar `resetForm()` tras guardados exitosos.

## 5. Manejo de Errores
- **Contextual Errors**: Usar el patrón `FirestorePermissionError` y `errorEmitter` para fallos de reglas de seguridad.
